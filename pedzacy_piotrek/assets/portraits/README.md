# Character portraits

The picture of a character's face, shown at the top of the right-hand panel
above its name. Drop a file in this folder and that character starts using it.

Every character **without** a picture here shows `placeholder.png` instead, so
portraits can be drawn one at a time, over months, and nothing has to be
finished all at once.

## The whole workflow

1. Make the portrait.
2. Save it here, named after the **character**: `Glockboy.png`.
3. That's it. No JSON, no code.

```
portraits/
    placeholder.png      <- the fallback, used by everyone with no file
    Piotrek.png
    Glockboy.png
    Big D Randy.png
    Lubin.png
```

## Replacing the placeholder

Overwrite `placeholder.png` with any image. Nothing else changes — no
configuration names it, and no rendering code names it. It is the one file in
this folder that is not a character.

## How a file finds its character

The filename and the character's name are both reduced to a *key* and compared,
using **exactly** the folding `card_art/` uses, so the spelling does not have to
be exact:

| File | Key | Matches the character |
|---|---|---|
| `Glockboy.png` | `glockboy` | Glockboy |
| `Big D Randy.png` | `big_d_randy` | Big D Randy |
| `big-d-randy.PNG` | `big_d_randy` | Big D Randy |
| `Dziubdziuch.jpg` | `dziubdziuch` | Dziubdziuch |
| `Stanczyk.png` | `stanczyk` | Stańczyk |

Case, spaces, hyphens, punctuation and Polish diacritics all fold away.

There are **no deck subfolders** here, unlike `card_art/`. Card art needs them
because "Shady" is a title in two decks; a character name is unique, so this
folder is flat and stays flat.

## The character's name — *not* the ability's

This is the distinction stage 49 exists to enforce, and it is easy to get
backwards:

| | Goes in | Named after |
|---|---|---|
| Big D Randy's **face** | `portraits/` | `Big D Randy.png` |
| Granny Costume's **card art** | `card_art/` | `Granny Costume.png` |

`Big D Randy` is the character. `Granny Costume` is the ability printed on his
card. They are two different pictures in two different folders, and neither
lookup can reach the other's — a character cannot borrow its ability's artwork,
and an ability cannot borrow its owner's face.

## Formats

`.png`, `.jpg`, `.jpeg`, `.webp`, `.bmp`. If both `Piotrek.png` and
`Piotrek.jpg` exist, PNG wins.

## What to draw

* **Roughly square**, a little taller than wide. The frame is about 0.94 wide
  for every 1.0 tall, and the picture is scaled to *cover* it and centred, so
  the overflow on the long axis is cropped. Keep the face centred and away from
  the very edges.
* **No frame and no border.** The game draws the recessed well and the brass
  edge around your picture; a border baked into the file would appear twice.
  Same rule as `card_art/`.
* **No name.** The character's name is drawn underneath the portrait.
* **Around 512–640 px square is plenty.** The largest a portrait is painted is
  about 270 px in the panel, and roughly 500 px in the enlarged hover preview.

## When a picture is missing or broken

Nothing happens, on purpose. A character whose file has been deleted, half
downloaded, or renamed to `.png` from something that is not a PNG falls back to
`placeholder.png` and the game carries on. If even the placeholder is missing,
the panel draws an empty well. A portrait folder is filled in by hand over
months; it is expected to be incomplete, and an incomplete folder must never be
able to stop a game.

## Regenerating the placeholder

The shipped `placeholder.png` is a brass bust on the panel's own dark field,
generated by:

```
python tools/make_portrait_placeholder.py
```

That script exists so the placeholder can be re-tuned without hand-editing a
binary. It is **not** part of the build or the tests — the committed PNG is the
asset. Anyone replacing the placeholder with real art should overwrite the file
and ignore the script.
